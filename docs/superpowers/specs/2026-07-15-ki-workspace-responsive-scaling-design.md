# KI 中部工作舞台响应式缩放设计

## 目标

让内容采集及后续复用 KI 导航模板的页面，在大屏与小屏上保持一致的舞台构图和信息密度。小屏不再只是缩小外层可用区域并裁切内部内容，而是对中部工作舞台进行真实缩放，从而显示更多列表项和详情内容。

今日知几保持独立布局，不接入本方案。

## 设计决定

采用模板级中部舞台缩放，不缩放顶部导航、底部 Dock、背景和弹窗。

- `2560 x 1440`：工作舞台缩放比例为 `1`。
- `1440 x 900`：工作舞台缩放比例约为 `0.86`。
- `1180 x 820`：工作舞台缩放比例约为 `0.78`。
- 两档基准之间连续变化，避免跨断点时突然跳变。
- 缩放比例设置下限，防止更窄窗口中文字失去可读性。

## 模板结构

`KiNavigationShell` 提供统一的 `--ki-workspace-scale`。中部内容容器保留原来的屏幕定位，内部舞台使用该变量缩放。

缩放后的舞台需要进行反向尺寸补偿：逻辑宽度和高度分别除以缩放比例，再通过 `transform: scale(...)` 映射回外层可用区域。这样可以增加内部可排布空间，同时保持舞台最终视觉边界不变。

变换原点使用顶部中央：

- 顶部与导航区的视觉间距保持稳定。
- 左右内容仍围绕当前舞台中心对齐。
- 不改变搜索框、品牌、导航和 Dock 的坐标系统。

## 内容采集兼容修复

旧内容采集根节点带有 `min-height: 100svh`。嵌入模板时必须覆盖为 `min-height: 0` 和 `height: 100%`，否则内部仍按完整视口高度排版并被外层裁切。

列表滚动区域需要：

- 使用剩余舞台高度，设置 `flex: 1` 和 `min-height: 0`。
- 保持隐藏滚动条和现有懒加载逻辑。
- 不改变列表项视觉样式、选中逻辑和详情切换逻辑。

## 范围

本轮先接入内容采集页，并将缩放变量和容器规则放在共享 KI 模板层，供系统中枢、专题、产业链、工具箱等同结构页面复用。

不调整：

- 顶部导航尺寸与位置。
- 底部 Dock 尺寸与位置。
- 弹窗和浮窗缩放。
- 今日知几页面。
- 内容字段、接口和业务行为。

## 验收

在 `2560 x 1440`、`1440 x 900`、`1180 x 820` 三档验证：

- 中部舞台不穿过顶部导航或底部 Dock。
- 列表、分类 Tab、详情区和详情 Tab 同步缩放。
- 小屏可见列表项数量明显多于修改前。
- 左右分栏比例和顶部对齐关系保持稳定。
- 搜索框、顶部导航、Dock 和弹窗不随中部舞台缩放。
- 页面不存在横向溢出、文字裁切和不可操作区域。

自动验证包括组合测试、Vite 构建和 `git diff --check`；视觉验证使用三档固定视口截图和 DOM 几何测量。
