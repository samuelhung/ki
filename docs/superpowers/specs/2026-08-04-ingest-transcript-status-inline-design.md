# 内容详情转写状态同行设计

## 背景

内容采集页的内容详情头部目前把“转写处理”按钮和转写状态一起放在 `.transcript-title-actions` 中。该容器纵向排列，因此“已人工校验 · 2026/8/4 17:58:01”或“原始转写”固定显示在按钮下方；内容创建时间和分类则由标题行之后的独立 `<small>` 渲染。两段信息属于同一内容元数据层级，却被拆在左右两个区域。

## 目标

- “转写处理”按钮继续位于标题右侧。
- 内容创建时间、分类和转写状态位于标题下方同一行。
- 已人工校验时按以下顺序显示：`2026/8/4 17:27:05 · 认知 · 已人工校验 · 2026/8/4 17:58:01`。
- 未处理时按以下顺序显示：`2026/8/4 17:27:05 · 认知 · 原始转写`。
- 加载、错误和刷新状态继续可见、可操作，并与内容元信息处于同一行。

## 非目标

- 不修改转写修订数据、北京时间格式或后端接口。
- 不改变“转写处理”按钮的文案、图标、样式和打开工作台的行为。
- 不改变人工修正、AI 语义分段、恢复历史版本或摘要失效流程。
- 不调整独立事件详情页的现有头部布局。
- 不推送、合并或部署；这些动作需要后续明确授权。

## 设计方案

将转写操作控件和转写状态拆成两个可复用展示单元：

- `TranscriptActionButton` 只负责“转写处理”按钮及其禁用状态。
- `TranscriptStatus` 只负责原始、人工校验、语义分段、恢复、加载、错误和刷新展示。
- 现有 `TranscriptActions` 继续组合这两个单元，供独立事件详情页保持原布局。

内容采集页不再把整个 `TranscriptActions` 节点放入标题行，而是分别传递按钮节点和状态节点：

- 按钮节点位于 `.transcript-title-row` 右侧。
- 状态节点位于新的 `.ingest-detail-meta-row` 中，紧跟内容创建时间和分类。

这样既让内容采集页获得正确的信息层级，也避免把内容时间和分类反向耦合进转写按钮组件。

## 展示规则

元信息行从左到右固定为：

`内容创建时间 -> 分隔点 -> 分类 -> 分隔点 -> 转写状态 -> 可选修订时间 -> 可选刷新按钮`

转写状态文本继续由现有规则产生：

| 修订类型 | 显示文本 |
| --- | --- |
| `original` | 原始转写 |
| `manual` | 已人工校验 · 北京时间 |
| `segmented` | 已完成语义分段 · 北京时间 |
| `restored` | 已恢复历史版本 · 北京时间 |

加载时显示“加载转写版本…”。请求失败时显示现有错误文本；需要刷新时，刷新按钮紧跟错误或状态，不移动到标题操作区。

转写状态和按钮仍只在“转写原文”标签页显示。切换到其他标签页后，内容创建时间与分类保留，转写状态和按钮隐藏，保持当前行为边界。

## 响应式布局

- 桌面和常规窄屏中，元信息保持单行排列，不与标题或按钮重叠。
- 可收缩空间优先分配给转写状态；内容创建时间、分类和刷新按钮不被压缩。
- 极窄手机宽度下，元信息容器保持单行并允许自身横向滚动，不制造页面级横向溢出；滚动条继续隐藏。
- 状态错误文本可以省略，但完整错误继续通过 `title` 暴露；刷新按钮必须保持可见。

## 组件范围

- `TranscriptActions.tsx`：提取按钮和状态子组件，保留现有组合组件兼容独立事件详情。
- `Ingest.tsx`：基于同一转写工作流状态创建按钮节点和状态节点。
- `IngestWorkspaceContent.tsx`：分别转发按钮和状态节点。
- `ContentDetailPanel.tsx`：标题行只接收按钮；新增元信息行组合内容时间、分类和转写状态。
- `ingestPageComposition.test.mjs`：锁定按钮与状态分别进入标题行和元信息行的组件契约。
- `eventDetailComposition.test.mjs`：锁定独立事件详情继续使用组合式 `TranscriptActions`。
- `DualNavigationDemo.css`：定义嵌入式内容详情元信息行的单行、收缩和极窄屏滚动规则。

## 测试策略

实施采用测试先行：

1. 增加组合测试，要求 `TranscriptActions` 导出独立按钮和状态单元，并要求内容详情把二者放入不同的语义区域。
2. 覆盖 `original`、`manual`、`segmented`、`restored`、加载、错误和刷新展示，确认文本和北京时间规则不变。
3. 先运行新增测试确认因当前纵向结构失败，再实施最小组件拆分。
4. 运行内容采集与事件详情定向测试、完整前端测试、TypeScript 检查和生产构建。
5. 在真实内容详情中分别验证“原始转写”和“已人工校验”状态；检查 `1280x720`、`2048x768` 和手机窄屏。
6. 通过 DOM 几何确认元信息各项处于同一行、刷新按钮可见、详情面板无新增水平溢出。

## 验收标准

- “转写处理”按钮只显示在标题右侧，不再携带下方状态行。
- “原始转写”与“创建时间 · 分类”处于同一行。
- “已人工校验 · 修订时间”与“创建时间 · 分类”处于同一行。
- 语义分段和历史恢复状态遵循相同布局。
- 加载、错误和刷新行为完整保留。
- 独立事件详情页无布局回归。
- 自动化测试、类型检查、生产构建和真实浏览器验证全部通过。
