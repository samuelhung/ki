# 内容采集标题编辑与 AI 候选设计

## 背景

内容采集详情目前只能展示采集阶段写入的标题，用户无法在系统内修正标题。详情标题右侧已有“转写处理”按钮，但按钮包含文字，占用较多横向空间；内容标题的修正也缺少人工输入和 AI 辅助入口。

## 目标

- 在内容详情标题右侧增加“修改标题”入口，并与“转写处理”并排。
- 两个入口都改为相同尺寸的纯图标按钮，通过 `title` 和 `aria-label` 提供名称。
- 用户可以直接输入显示标题，也可以根据当前生效转写生成 3 个 AI 候选标题。
- 点击 AI 候选只回填输入框，用户确认保存前可以继续修改。
- 保存只更新系统显示标题，永久保留采集到的原始标题。
- 保存后同步更新详情标题和左侧内容列表。

## 已确认决策

- 采用随行稿中的 A 方案“统一编辑”：输入框始终可用，AI 候选显示在同一弹窗中。
- 原始采集标题保存在 `events.title`，人工或 AI 确认的显示标题写入 `events.title_cn`。
- AI 读取当前生效的转写修订；没有修订时使用原始转写。
- AI 每次必须返回 3 个不重复的中文候选标题。
- 每个 AI 候选去除首尾空白后的总长度必须为 1–20 个字符，20 个字符可以；汉字、标点、数字和英文字母都计入长度。
- 手动输入标题去除首尾空白后的总长度同样必须为 1–20 个字符，20 个字符可以；计数规则与 AI 候选一致。
- AI 生成不进入处理队列，在弹窗内即时完成。

## 非目标

- 不覆盖或删除 `events.title`。
- 不增加标题修订历史、撤销记录或批量改名。
- 不根据标题变化自动重新生成摘要、分类、标签或转写。
- 不把标题生成任务接入处理队列。
- 不改变独立事件详情页、万象资料页或其他内容详情入口。
- 不推送、合并或部署；这些动作需要后续明确授权。

## 交互设计

### 标题操作区

“转写原文”标签页的标题右侧显示两个 30px 见方的图标按钮：

1. `Pencil`：修改标题，`title` 和 `aria-label` 均为“修改标题”。
2. `FilePenLine`：转写处理，`title` 和 `aria-label` 均为“转写处理”。

按钮顺序固定为“修改标题、转写处理”，间距和现有紫色操作样式保持一致。两个按钮仍只在“转写原文”标签页显示；窄屏允许操作组整体换到标题下方，但两个按钮自身不拆行、不裁切。

### 标题编辑弹窗

弹窗复用现有共享 `Modal` 的焦点管理、遮罩、关闭按钮和 Escape 行为，并采用紧凑暗色样式。弹窗内容从上到下为：

1. “显示标题”输入框，打开时带入 `title_cn || title`。
2. “AI 生成”按钮；生成中显示加载状态并禁止重复生成。
3. AI 候选区域；未生成时不占用空候选卡片。
4. 错误或校验提示。
5. “取消”和“保存标题”按钮。

点击任一候选会将其写入输入框并标记为选中，但不会自动保存。用户随后修改输入框时，若文本不再等于任何候选，则清除候选选中态。重新生成会替换上一批候选，但不会覆盖用户当前输入。

关闭、取消、切换内容或切换分类会丢弃未保存内容，并取消尚未完成的 AI 请求。保存成功后关闭弹窗；保存失败时保留输入和候选。

## 后端设计

### 标题保存服务

新增聚焦的 `event_title_service.py`，负责标题规范化、事件存在性检查和数据库更新。服务不接收或修改原始标题。

新增接口：

```http
PUT /api/events/{event_id}/title
Content-Type: application/json

{"display_title":"新的显示标题"}
```

请求模型使用 Pydantic `field_validator` 先执行 `strip()`，再校验规范化后的长度为 1–20 个字符；服务层复用同一规范化函数，避免路由和数据库写入规则漂移。成功时只执行：

```sql
UPDATE events SET title_cn = ? WHERE id = ?
```

响应返回 `id`、`title` 和 `title_cn`，让前端用同一个确认结果更新详情与列表。未知事件返回 404；空标题或超长标题返回 422。

### AI 候选服务

新增接口：

```http
POST /api/events/{event_id}/title/suggestions
```

接口不接收前端原文。服务通过 `transcript_revision_service.get_transcript()` 读取当前生效修订的 `active_revision.content`；没有可用文本时返回 400。

服务调用现有统一 `ai_client.chat()`，使用标题生成专用 `module` 和 `task`，关闭 thinking，使用低温度和 `response_format={"type":"json_object"}`。提示词要求模型只返回：

```json
{"titles":["标题一","标题二","标题三"]}
```

后端对返回值执行完整校验：

- 必须是包含 `titles` 数组的 JSON 对象。
- 必须恰好有 3 个字符串。
- 每项 `strip()` 后不能为空。
- 每项按 Python 字符串长度计算必须小于等于 20；标点、数字和英文字母同样计数。
- 3 个候选必须完全不同。

任一条件不满足时整批拒绝，不把不完整候选返回前端。AI 未配置、超时、空响应、无效 JSON 或候选校验失败统一映射为稳定的 502 响应，日志不得包含原文或凭据。

## 前端架构

### 组件边界

- `TranscriptActionButton` 改为纯图标按钮，继续只负责转写入口和禁用状态。
- 新增 `TitleActionButton`，只负责修改标题入口。
- 新增 `TitleEditorDialog`，拥有输入、候选、生成、保存、错误和请求取消状态。
- `ContentDetailPanel` 接收统一的标题操作节点，不直接拥有弹窗业务状态。
- `Ingest.tsx` 组合两个图标按钮并挂载 `TitleEditorDialog`。

标题弹窗逻辑不塞进 `ContentDetailPanel`，避免共享详情组件耦合内容采集页专属写操作。

### 状态同步

保存成功后使用响应中的 `title_cn` 同步两处状态：

- `useIngestEvents` 提供 `updateEventTitle(eventId, titleCn)`，只更新当前事件列表快照。
- `useIngestDetailActions` 提供同名局部更新函数，只在当前详情 ID 匹配时更新详情。

这样标题立即更新，且不触发整页列表重新加载。后续正常加载仍以数据库为准。

### 请求生命周期

AI 生成和标题保存分别使用独立 `AbortController`。关闭弹窗、切换活动事件或组件卸载时取消未完成请求；迟到响应不得更新新事件的弹窗状态。保存期间弹窗不可重复提交，但不阻塞已有标题的阅读。

## 校验与错误状态

- 手动输入为空：显示“请输入标题”，保存按钮禁用。
- 手动输入超过 20 个字符：显示“标题不能超过 20 个字符”，保存按钮禁用。
- 没有可用转写：手动输入保持可用，AI 区域显示“当前内容没有可用原文”。
- AI 失败：保留当前输入和上一批候选，仅显示稳定错误。
- 保存失败：保留弹窗、输入和候选，允许重试。
- 保存成功：关闭弹窗，显示现有风格的成功提示，并更新详情和列表。

## 测试策略

实施严格采用测试先行：

1. 后端服务测试先覆盖显示标题规范化、只更新 `title_cn`、原始 `title` 不变、20 个字符通过、21 个字符返回 422。
2. AI 服务测试先覆盖当前生效转写读取、恰好 3 个候选、去重、JSON 失败，以及 20 个字符通过、21 个字符拒绝。
3. 路由测试覆盖 HTTP 方法、响应结构和 400/404/422/502 映射。
4. 前端纯逻辑测试覆盖候选选择回填、手动修改清除选中态、重新生成不覆盖输入、请求取消和迟到响应抑制。
5. 组合测试锁定两个纯图标按钮、无可见按钮文字、工具提示和无障碍名称、弹窗挂载点及列表/详情同步回调。
6. 运行完整后端测试、前端 `test:cinematic-scene`、TypeScript 检查和生产构建。
7. 在真实内容上验证手动保存、AI 三候选、20 字边界、桌面与手机弹窗、按钮裁切和页面横向溢出。

## 验收标准

- 标题右侧只显示两个同尺寸图标按钮，顺序和工具提示正确。
- 原始 `events.title` 在任何标题修改后保持不变。
- 手动标题可输入、保存，并立即同步到详情与左侧列表。
- 手动标题和 AI 候选均限制为 1–20 个字符，使用相同计数规则。
- AI 根据当前生效转写返回恰好 3 个不重复标题。
- 每个 AI 候选总长度不超过 20 个字符，20 字可用，21 字整批拒绝。
- 点击候选只回填输入框，保存前允许继续修改。
- AI 或保存失败不会丢失当前编辑内容。
- 切换内容后不存在前一事件的迟到候选或保存结果污染。
- 自动化测试、类型检查、构建和真实浏览器验证全部通过。
