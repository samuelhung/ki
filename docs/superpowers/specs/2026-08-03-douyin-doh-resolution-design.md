# 抖音媒体 Fake-IP 的 DoH 解析设计

## 背景

生产代理使用 Fake-IP DNS。抖音媒体链路中的主机名会解析到
`198.18.0.0/15`，而通用远程媒体传输要求目标地址是公网 IP，因此任务在下载
阶段失败。

失败任务 `task-d7ff5704ef2c` 的实测重定向链为：

```text
aweme.snssdk.com
  -> v5-se-qn-daily-cm-cold.douyinvod.com
  -> 1911581983.qrstuvwxyzab.com
```

三个主机名都被系统 DNS 映射到 `198.18.0.0/15`。逐个维护域名白名单无法
覆盖动态 CDN；像普通 `requests` 一样无条件跟随重定向又会削弱现有 SSRF
防护。

生产只读取样已经验证：通过 Google Public DNS 的 DoH 获取每一跳的真实
公网 IP，再保留现有的固定 IP 连接和原始 TLS 主机名，可以得到 HTTP 200
并读取视频字节。

## 目标

- 抖音媒体下载遇到代理 Fake-IP 时，通过固定的受信任 DoH 服务获取真实公网
  IP。
- 保留逐跳 URL 校验、DNS 重绑定防护、TLS 证书校验、SNI 和 Host 语义。
- 普通私网、回环、链路本地和其他非公网地址继续失败关闭。
- 不影响通用远程媒体传输，也不把 DoH 解析能力开放给任意调用方。
- 删除此前针对少数抖音域名的 Fake-IP 地址例外，避免两套安全模型并存。

## 非目标

- 不恢复无限制的 `requests` 自动重定向下载。
- 不维护抖音 CDN 域名后缀白名单。
- 不修改生产代理的 Fake-IP 配置。
- 不改变分享链接解析、视频大小限制、任务队列或北京时间展示逻辑。
- 不把 DoH 端点做成用户可配置的任意 URL。

## 方案比较

### 方案 A：Fake-IP 专用 DoH 回退（采用）

系统 DNS 正常返回公网 IP 时沿用现有结果；只有全部结果都属于
`198.18.0.0/15` 时，查询固定的 Google Public DNS DoH 端点。DoH 返回的地址
仍必须通过公网 IP 校验。

该方案适配动态 CDN，同时保留现有固定 IP 和逐跳验证边界。

### 方案 B：代理 Fake-IP 过滤

需要枚举动态 CDN 域名。当前链路已经出现随机化域名，过滤规则会持续漂移，
不能作为应用层稳定方案。

### 方案 C：信任抖音重定向并允许任意 Fake-IP

实现简单，但上游响应可以把下载器引向任意目标，应用无法区分代理 Fake-IP
与需要拒绝的目标，安全边界不足。

## 架构

### 组件边界

新增一个抖音专用解析模块，职责仅包括：

1. 调用现有系统解析器。
2. 判断解析结果是否全部属于代理 Fake-IP 网段。
3. 必要时调用固定 DoH 端点查询 A 和 AAAA 记录。
4. 只返回格式有效的公网 IP；否则抛出稳定、安全的解析错误。

`remote_transport` 继续负责 URL 结构校验、目标 IP 公网性校验、固定 IP 连接、
重定向次数和逐跳验证。它不感知 DoH，也不改变默认行为。

`douyin` 下载门面将新的抖音解析器作为 `download_video` 的默认 resolver。测试
仍可注入自定义 resolver。

### DoH 端点

固定使用：

```text
https://dns.google/resolve
```

请求分别查询 `A` 和 `AAAA`。DoH 调用使用独立请求，不复用抖音 Session，
因此不会向 DNS 服务发送抖音 Cookie 或媒体请求头。端点通过普通 HTTPS 证书
验证，不接受调用方覆盖。

### 触发规则

系统解析结果分为三类：

1. 包含公网 IP：直接返回系统结果，不调用 DoH。后续通用校验只选择公网 IP。
2. 所有地址都位于 `198.18.0.0/15`：允许调用 DoH。
3. 任何其他非公网情况：原样返回系统结果，由现有校验拒绝，不调用 DoH。

第三类包括但不限于：

- `127.0.0.0/8`
- RFC 1918 私网
- 链路本地地址
- IPv6 回环、唯一本地和链路本地地址
- 混合 Fake-IP 与普通私网的结果

这一规则保证 DoH 不能把内网或分割 DNS 名称转换成公网访问。

### DoH 响应校验

- HTTP 请求必须成功。
- DNS JSON `Status` 必须为 `0`。
- 只接受类型为 `A` 或 `AAAA` 的 Answer。
- 每个地址必须能被 `ipaddress.ip_address` 解析。
- 只返回 `is_global` 为真的地址。
- 空结果、格式错误、非公网结果、超时和网络错误全部失败关闭。
- 错误信息不包含完整媒体 URL、Cookie、请求头或 DoH 响应正文。

本次不加入跨请求 DNS 缓存。媒体 URL 有时效性，避免无 TTL 缓存引入新的过期
和路由问题。

## 下载数据流

```text
抖音详情返回媒体 URL
  -> 系统 DNS
  -> 公网 IP：沿用
  -> 全部为 198.18/15：固定 DoH 查询真实 IP
  -> 现有 remote_transport 校验公网 IP
  -> 固定连接到验证后的真实 IP
  -> TLS/SNI/Host 使用原始主机名
  -> 收到重定向后从系统 DNS 步骤重新执行
```

DoH 只改变候选 IP 的来源，不改变 HTTP 请求目标、Cookie 作用域、重定向上限、
响应大小限制或目标文件清理语义。

## 安全属性

- 通用传输仍默认拒绝所有非公网解析结果。
- 抖音解析器只对确切的 `198.18.0.0/15` Fake-IP 情况启用 DoH。
- 普通私网不会触发 DoH。
- DoH 返回的私网地址不会进入连接层。
- 每一跳重新解析、重新校验并重新固定 IP。
- TLS 证书、SNI 和 Host 始终使用该跳原始域名，不能使用 DoH 返回内容覆盖。
- 删除 `aweme.snssdk.com` 和 `365yg.com` 的 Fake-IP 直连例外。

## 错误处理与可观测性

解析失败继续进入现有任务错误处理和用户安全提示。服务端可以记录安全的错误
类别，例如系统解析失败、DoH 请求失败、DoH 无公网结果，但不记录完整签名
URL 或响应正文。

DoH 不可用时任务失败，不回退为连接 Fake-IP 或无条件 `requests` 下载。

## 测试策略

### 解析器单元测试

- 系统返回公网 IP 时不调用 DoH。
- 系统只返回 `198.18.0.0/15` 时查询 DoH 并返回公网 A/AAAA。
- 回环、普通私网、链路本地结果不调用 DoH。
- Fake-IP 与普通私网混合时不调用 DoH。
- DoH 非零状态、空 Answer、无效 IP、私网 IP、超时和请求错误均失败关闭。
- DoH 请求不携带抖音 Session、Cookie 或媒体请求头。

### 传输集成测试

- `aweme.snssdk.com -> douyinvod.com -> 动态 CDN` 每一跳都重新调用解析器。
- 每个连接使用 DoH 返回的公网 IP。
- TLS hostname、SNI 和 Host 保留每一跳的原始主机名。
- 通用 `remote_transport` 继续拒绝 Fake-IP 和普通私网。
- 下载大小、重定向次数、Cookie 域作用域和失败文件清理测试继续通过。

### 回归验证

- 后端全量测试、Ruff 和构建通过。
- 前端测试、TypeScript 和生产构建保持通过，因为北京时间修复与本次后端变更
  将共同进入制品。
- wheel 内容检查确认包含新的解析模块和北京时间前端资源。

## 部署与验收

目标版本为 `2.0.0+108`，继续使用 SHA 专属制品目录、x86_64 wheelhouse、完整
SHA256 清单、只读 preflight、原子部署和 `--preserve-history`。

上线后必须验证：

1. `runtime/current` 指向 `2.0.0+108`，`2.0.0+107` 保留用于回滚。
2. launchd、监听端口、认证健康接口和数据库完整性正常。
3. 通过现有认证 API 重试 `task-d7ff5704ef2c`，不直接修改数据库。
4. 任务越过下载、保存、音频提取、转写和后续阶段，最终状态为 `done`。
5. 处理队列仍显示北京时间 `2026/8/3 17:56:03`，桌面和窄屏布局正常。
6. 至少观察 30 秒，确认没有新的服务错误或任务回退。

如果 DoH 方案导致服务异常，立即恢复 `runtime/current` 到保留的
`2.0.0+107` 并恢复 launchd 健康，再进行诊断。
