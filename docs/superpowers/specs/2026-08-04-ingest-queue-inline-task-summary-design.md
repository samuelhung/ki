# 处理队列任务信息同行设计

## 背景

当前全局处理队列把任务标题、任务级提示、北京时间、状态和操作拆成多列，其中任务级提示位于标题下方。运行任务因此形成两层主信息，“运行中”还可能重复出现，压缩了节点轨道上方的有效空间。

本次调整采用已确认的网页稿：任务标题、任务级文案、运行状态、北京时间和操作按钮全部放在同一排；全链路节点轨道继续独立显示在下一行。

## 目标

- 处理中任务在一排内依次显示：标题、处理中、运行中、北京时间、删除按钮。
- 标题弹性占用剩余宽度，过长时单行省略，状态、时间和操作不得被挤压或换行。
- 节点轨道继续位于主信息行下方，不改变节点顺序、状态颜色、实时刷新或移动端横向定位。
- 等待、异常和完成任务使用同一结构，保持队列扫描节奏一致。

## 非目标

- 不修改队列接口、轮询频率、节点定义或任务排序。
- 不改变重试、删除、北京时间格式或空队列行为。
- 不改变处理队列弹窗宽度、头部、统计区或工具栏。
- 不调整节点轨道本身的视觉和交互。

## 信息结构

每个任务继续保留左侧状态图标。图标右侧改为一个主信息行，顺序如下：

`任务标题 -> 任务级文案 -> 运行状态 -> 北京时间 -> 操作按钮`

任务级文案与运行状态分工如下：

| 任务状态 | 任务级文案 | 运行状态 |
| --- | --- | --- |
| `running` | 处理中 | 运行中 |
| `pending` | 等待处理 | 等待中 |
| `error` | 接口错误信息；缺失时显示“处理异常” | 异常 |
| `done` | 处理完成 | 已完成 |

异常任务保留错误详情和重试按钮。错误详情使用和标题相同的单行省略策略，不能挤掉异常状态、时间、重试或删除按钮。

## 响应式布局

### 桌面端

- 任务主行使用图标列加一个可收缩的信息内容列。
- 信息内容列使用单行弹性布局；标题优先获得剩余空间并允许收缩。
- 任务级文案、运行状态、北京时间和操作按钮保持固定内容宽度，不换行。
- 节点轨道继续从内容列开始横跨至任务行末尾。

### 窄屏

- 标题、任务级文案、运行状态和操作按钮保持同一排。
- 北京时间继续隐藏，避免状态和删除按钮被挤出可视区域。
- 标题和异常详情允许省略；状态与操作保持完整。
- 节点轨道继续使用现有横向滑动和当前节点自动定位。

## 组件改动

`GlobalDockQueueOverlay.tsx` 增加任务级文案映射，并将标题、任务级文案、状态、时间和操作包进一个任务摘要容器。现有 `QueueProgressTrack`、队列 hook 和操作回调保持不变。

`GlobalDockQueueOverlay.css` 将任务主网格简化为图标列和内容列；摘要容器负责单行排列、截断和响应式隐藏时间。现有状态颜色、按钮样式和节点轨道样式继续复用。

## 可访问性

- 标题完整文本继续保留在 DOM 中，并通过 `title` 提供鼠标悬停查看。
- 状态文本不只依赖颜色表达。
- 重试和删除按钮继续使用包含任务标题的 `aria-label`。
- 视觉顺序与 DOM 顺序一致。

## 测试

实施采用测试先行：

1. 增加组合回归断言，要求标题、任务级文案、状态、时间和操作位于同一摘要容器。
2. 覆盖四种任务状态的任务级文案映射以及异常错误详情降级。
3. 覆盖桌面端单行弹性布局、标题省略和固定操作区。
4. 覆盖窄屏只隐藏时间，状态和操作仍可见。
5. 运行相关 Node 测试、TypeScript 检查和生产构建。
6. 在真实处理队列中检查桌面和窄屏：无文字重叠、无页面横向溢出、节点轨道可用、按钮可点击。

## 验收标准

- 运行任务在一排中完整呈现“标题、处理中、运行中、北京时间、删除”。
- 标题过长时省略，状态、时间和操作不被挤掉。
- 窄屏隐藏时间，其余主信息仍在一排且可操作。
- 异常任务的错误信息、重试和删除保持可用。
- 节点轨道的顺序、实时状态、横向滑动和自动定位无回归。
