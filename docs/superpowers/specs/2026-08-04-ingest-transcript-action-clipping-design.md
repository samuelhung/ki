# 内容详情转写处理按钮裁切修复设计

## 背景

内容采集页选中一条内容后，详情标题右侧的“转写处理”按钮和下方转写状态会被详情面板右边界裁切。生产页面实测时，详情面板右边界约为 `1893.5px`，内部 `.ingest-detail-reader`、标题行和按钮的右边界约为 `1904.95px`，超出约 `11.45px`。

根因是 `.ki-ingest-detail-pane` 带有左侧内边距，而其子元素 `.ingest-detail-reader` 同时使用 `width: 100%`。当前盒模型下，子元素从父容器内容区起点开始占用父容器完整宽度，最终向右多伸出一段等同于左侧内边距的距离。父容器使用 `overflow: hidden`，因此贴右对齐的转写操作区被裁切。

## 目标

- “转写处理”按钮和转写状态始终完整位于内容详情面板内。
- 保留当前标题、按钮、状态、视频和详情标签页的视觉位置与交互。
- 长标题继续使用现有弹性布局，不因修复而挤压操作区或标签页。
- 消除详情阅读区由盒模型造成的水平溢出。

## 非目标

- 不修改“转写处理”按钮的文案、图标、样式、尺寸或功能。
- 不调整内容详情左右分栏比例、面板间距或整体窗口宽度。
- 不修改转写工作台、修订记录、人工修正或 AI 语义分段流程。
- 不修改视频播放器、详情标签页或内容数据接口。
- 不合并主干、不推送远端、不部署生产；这些动作需要后续明确授权。

## 设计方案

采用盒模型修复：让嵌入式内容详情中的 `.ingest-detail-reader` 在 `width: 100%` 时把自身尺寸计算在父容器可用宽度内。现有父容器左侧留白继续保留，阅读区的视觉起点不变；阅读区右边界回到父容器内部，不再依赖额外右侧留白掩盖溢出。

本次不改变标题行的 `flex-wrap`、标题内容或转写操作区的 `shrink-0` 规则。按钮仍位于标题行右侧，空间不足时继续遵循现有标题行换行行为。

## 组件与样式范围

- `DualNavigationDemo.css`：在嵌入式内容详情的既有布局规则中修正阅读区盒模型，确保宽度包含自身尺寸。
- `kiLegacyIngestShellComposition.test.mjs`：增加 CSS 契约断言，防止 `width: 100%` 与父容器内边距再次组合成水平溢出。
- `ContentDetailPanel.tsx`、`TranscriptActions.tsx` 保持不变；现有 DOM 结构已经正确表达标题与操作区关系。

## 测试策略

实施采用测试先行：

1. 先增加组合回归测试，要求嵌入式详情阅读区使用不会超出父容器的盒模型，并确认测试在生产代码未改动时按预期失败。
2. 添加最小 CSS 修复，确认定向测试转绿。
3. 运行内容采集相关测试、完整前端测试、TypeScript 检查、生产构建和 `git diff --check`。
4. 在已登录的真实生产页面记录修复前几何数据；本地构建后使用相同内容和窗口宽度记录修复后几何数据。
5. 检查详情面板、阅读区、标题操作区和按钮的右边界，要求阅读区及按钮均不超过详情面板可见右边界。
6. 视觉检查标题、转写状态、视频和四个详情标签页，确认无裁切、重叠或新增横向滚动。

## 验收标准

- “转写处理”按钮的文字、图标、边框和右侧留白完整可见。
- 按钮下方的“原始转写”或其他修订状态完整可见。
- `.ingest-detail-reader` 的可见右边界不超过 `.ki-ingest-detail-pane` 的右边界。
- 标题保持完整显示或按现有规则换行，不与按钮重叠。
- 视频和详情标签页宽度正常，无新增水平溢出。
- 自动化测试、类型检查和生产构建全部通过。
