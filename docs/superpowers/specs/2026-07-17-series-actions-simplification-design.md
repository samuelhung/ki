# 专题系列筛选与操作简化设计

## 目标

在不减少专题能力的前提下，移除左侧无效状态筛选，降低右侧标题栏的操作噪声，并让 AI 生成动作与其产物建立清晰的一一对应关系。

## 当前问题

- 当前专题列表数据均为已发布，页面也没有草稿转发布的主流程；“发布 / 草稿”只占空间，没有形成有效工作流。
- 标题右侧同时排列导言、总结、深度分析、待办和删除操作，视觉权重接近，但前三项实际分别服务于不同内容区域。
- 当某项 AI 产物尚未生成时，空状态只提示用户回到顶部找按钮，操作与结果距离过远。

## 选定方案：内容就地操作

### 左侧专题列表

- 删除“全部 / 发布 / 草稿”状态 Tab。
- 删除 `seriesStatus` 本地状态及状态过滤逻辑，搜索只按标题和描述过滤全部专题。
- 列表顶部不增加新的卡片或筛选条，保持现有空间感。
- 专题自身的状态仍保留在数据和详情标题旁，避免改变后端模型和旧版页面能力。

### 右侧标题栏

- 移除“生成导言 / 生成总结 / 深度分析”三个按钮。
- 保留“添加待办”，作为跨内容区的专题级动作。
- 新增轻量“更多”菜单，只收纳删除专题；菜单关闭支持点击外部和 `Escape`。
- 删除继续使用现有确认弹窗，不改变危险操作保护。

### 专题导言

- 已有导言时，在“专题导言”小标题右侧显示“重新生成”。
- 没有导言时仍展示导言区域，用简短空状态和“生成导言”操作替代完全隐藏。
- 生成中禁用按钮并显示局部进度，不影响其他区域阅读。

### 结构化速览

- 在“结构化速览”Tab 的内容标题右侧显示“生成 / 重新生成”。
- 没有总结时，空状态内直接显示“生成结构化速览”。
- 继续复用现有总结生成接口、错误状态和内容同步逻辑。

### 深度分析

- 在“深度分析”Tab 的内容标题右侧显示“生成 / 重新生成”。
- 没有深度分析时，空状态内直接显示“生成深度分析”。
- 继续复用现有深度分析接口、错误状态和内容同步逻辑。

## 交互与视觉规则

- 就地操作沿用现有无胶囊、图标加文字、下横线高亮的操作语言。
- 同一时间只允许一个 AI 生成任务运行；继续使用现有三个 loading 状态判断。
- 标题栏不新增容器、背景卡片或粗边框。
- 小屏下操作文字必须保持可见，不依赖仅图标表达核心生成动作。
- “更多”菜单使用紧凑浮层，层级高于详情滚动区，但不改变详情宽度。

## 数据与兼容性

- 不修改专题 API、数据库状态字段或旧版专题页面。
- `filterSeriesItems` 保留状态参数能力，供旧逻辑和测试使用；新专题页面固定传入 `all` 或只执行文本搜索。
- 生成成功后仍通过现有 `onSeriesChange` 同步详情缓存和左侧列表元数据。

## 验证

- 组合测试确认新页面不再渲染状态 Tab，也不再持有 `seriesStatus`。
- 详情测试确认三个生成动作分别位于导言、速览和深度分析区域。
- 交互测试覆盖空产物、已有产物、生成中、生成失败和删除确认。
- 浏览器视觉检查覆盖 `2560x1440`、`1440x900`、`1280x720`、`1180x820`。
- 运行 `npm run test:cinematic-scene`、`npm run build` 和 `git diff --check`。

## 非目标

- 本轮不新增草稿发布流程。
- 本轮不修改专题发现、自由组题、扫描新内容或待确认建议流程。
- 本轮不重排专题正文、内容 Tab 或底部 Dock。
