# 处理队列全链路进度轨道设计

## 背景

抖音分享接入后端目前会持续写入十个处理节点：解析链接、下载视频、保存视频、提取音频、上传 TOS、语音转写、AI 总结、写入数据库、自动分类和完成。队列接口仍返回 `progress_stages`，活跃队列也会约每三秒刷新，但当前全局处理队列弹窗只显示任务级状态，没有渲染节点进度。

本次改动只恢复已有实时进度的可视化，不改变接入流程、队列接口、轮询频率、重试、删除或任务持久化行为。

## 目标

- 在当前全局处理队列中恢复任务的完整节点进度。
- 桌面端一次显示全部节点，便于快速定位任务所处阶段。
- 移动端允许在节点轨道内横向滑动，并让当前节点自动进入可视区域。
- 运行失败时明确标出失败所在节点。
- 保持当前弹窗的尺寸、信息层级、颜色语义和操作方式。

## 非目标

- 不增加 WebSocket、SSE 或新的后端接口。
- 不修改后端阶段定义或现有约三秒轮询策略。
- 不展开等待任务的空轨道。
- 不默认展开已完成任务的历史节点。
- 不改变重试、删除、时间显示或队列排序。
- 不直接修正数据库中旧任务遗留的阶段状态。

## 展示规则

### 运行任务

任务主行保持现有标题、时间、状态和操作列。主行下方新增全链路进度轨道，按接口顺序渲染 `progress_stages` 的全部节点。

- `done` 节点使用当前完成色。
- `active` 节点使用当前运行色，并显示“运行”。
- `pending` 节点保持弱化，并显示“等待”。
- 没有 `progress_stages` 时不渲染空轨道，任务主行继续正常显示。

### 失败任务

失败任务展开已有节点轨道。当前后端异常路径会保留一个 `active` 节点而不把它写成 `error`，因此当前任务状态为 `error` 时，轨道中第一个 `active` 节点按失败节点展示；若接口返回显式 `error` 节点，则直接使用该节点。失败节点使用当前异常色并显示“异常”。

重试后沿用接口返回的新状态，不在前端保留旧失败状态。

### 等待与完成任务

`pending` 和 `done` 任务保持现有紧凑行，不展开节点轨道。这样可避免多个历史任务挤占列表高度，并保留当前扫描效率。

## 响应式布局

### 桌面端

弹窗继续使用 `width: min(820px, calc(100vw - 48px))` 和现有内边距。轨道位于运行或失败任务主行下方，横跨任务内容区；全部节点在可用宽度内等分排列，不改变弹窗整体宽度。

节点文字允许单行截断，每个节点同时设置包含完整节点名称和状态的 `title` 与 `aria-label`。轨道高度固定，状态变化不得造成任务列表横向位移。

### 移动端

弹窗继续使用 `width: calc(100vw - 28px)`。节点轨道切换为单行横向滚动：

- 每个节点使用稳定的最小宽度，节点名称保持可读。
- 轨道使用 `overflow-x: auto`，不扩大页面或弹窗宽度。
- 轨道不换行，不改变队列的纵向滚动所有权。
- 当前或失败节点变化时，将对应节点滚入轨道可视区；不滚动整个页面。
- 支持触控横向滑动和键盘可访问的滚动区域。

## 组件与数据流

当前 `useIngestQueue` 继续负责轮询和队列状态。它的队列签名已经包含每个阶段的键与状态，因此节点状态变化会触发 React 更新，无需修改请求层。

在 `GlobalDockQueueOverlay` 的任务行内加入一个边界清晰的进度轨道渲染单元。该单元接收当前任务状态和 `progress_stages`，负责：

1. 判断任务是否需要显示轨道。
2. 将失败任务的遗留 `active` 状态映射为可见异常状态。
3. 渲染全部节点、状态标签和可访问名称。
4. 在窄屏状态变化后将当前或失败节点滚入视图。

后端阶段数据仍通过以下链路到达界面：

`process_ingest -> events.progress_stages -> /api/ingest/queue -> useIngestQueue -> GlobalDockQueueOverlay`

## 错误与降级

- `progress_stages` 缺失或为空：仅显示任务主行。
- 节点包含未知键：按接口提供的标签和状态顺序展示，不维护前端固定节点表。
- 找不到 `active` 或 `error` 节点：不自动伪造失败位置，保留任务级异常状态。
- 横向自动定位不可用：轨道仍可手动滑动，不影响任务操作。

## 测试

实施采用测试先行：

1. 增加组合回归测试，先证明当前队列未渲染 `progress_stages`。
2. 覆盖运行任务渲染全部节点，失败任务映射失败节点，等待和完成任务不展开。
3. 覆盖桌面十节点布局和移动端横向滚动规则。
4. 覆盖无进度数据时的降级行为。
5. 运行前端完整节点测试、媒体传输测试、质量门、TypeScript 类型检查和生产构建。
6. 使用真实队列弹窗在桌面与移动端视口检查：无横向页面溢出、轨道可滑动、当前节点可见、按钮可操作、文字不重叠。

## 验收标准

- 新提交的抖音任务在处理队列中显示十节点全链路实时进度。
- 节点状态随现有轮询更新，无需手动刷新。
- 失败任务能够定位到接口可确定的失败节点。
- 桌面端十节点完整呈现于正式弹窗宽度内。
- 移动端轨道可横向滑动，当前节点自动进入可视区，页面本身无横向溢出。
- 等待和完成任务保持紧凑。
- 原有重试、删除、北京时间及队列统计行为不变。
