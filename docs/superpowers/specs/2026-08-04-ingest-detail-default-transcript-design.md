# 内容详情默认转写与稳定 Tab 宽度设计

## 背景

内容采集页会在列表数据加载后自动选中第一条内容，也允许用户点击列表切换或重新选择当前内容。当前详情状态由 `useIngestDetailActions` 管理，它将 `detailTab` 初始化为 `summary`，并在详情请求完成后再次切到 `summary`。因此首次自动选中内容时不会落在“转写原文”；用户重复点击当前内容时，由于 `activeEventId` 没有变化，详情加载 effect 不会重新执行，原 tab 也会被保留。

生产页面还存在一个独立的宽度问题。嵌入详情栏本身宽约 818px，但 `.ingest-detail-reader` 最终命中 `width: auto`，使宽度由当前 tab 内容的固有尺寸决定。实测“转写原文”状态下 reader 宽约 807px，切到尚无内容的“AI 总结”后收缩到约 479px，内部四列 tab 随之一起收缩。

## 目标

- 选中普通内容后立即默认显示“转写原文”。
- 重复点击当前已选内容时也回到“转写原文”。
- 详情请求完成后不把普通内容切回其他 tab。
- 详情 reader 始终占满右侧详情 pane，不能随 tab 内容宽度变化。
- 四个详情 tab 始终在可用宽度内稳定等分，文字和图标不扩大网格列。
- 保持视频、转写工作台、AI 总结、关联问题、产业分析和 WebGL 场景的现有行为。

## 非目标

- 不重构内容列表或详情请求协调器。
- 不通过重新挂载整个详情面板来重置状态。
- 不修改视频播放、滚动位置、详情接口或摘要生成逻辑。
- 不调整 tab 的标签、顺序、颜色、图标和交互样式。
- 不改变独立事件详情页 `useEventDetail` 的现有 `user-concept` 规则。

## 交互设计

### 首次自动选中

列表加载完成并自动选中第一条普通内容时，详情 tab 使用 `body`。详情加载期间可以显示现有加载状态，但 tab 高亮和详情内容归属始终保持“转写原文”。请求完成后仍保持 `body`。

### 切换内容

点击另一条内容时，在发起详情请求之前同步切到 `body`。这样不会在网络请求期间短暂显示上一条内容的“AI 总结”“关联问题”或“产业分析”状态。

### 重复选择当前内容

列表点击入口必须显式通知详情状态重置，即使所点击的 event id 与当前 `activeEventId` 相同。该操作只切换 tab，不强制重发详情请求，不重置视频、详情内容或滚动容器。

### 手动切换

内容选定后，用户仍可自由切换四个 tab。只有新的内容选择动作会将其恢复到“转写原文”；详情数据刷新、摘要轮询完成等后台更新不得无故切换用户当前 tab。

## 状态与组件边界

`useIngestDetailActions` 继续拥有 `detailTab`。修复包含两个明确入口：

1. 详情 hook 的初始状态和选中 id 变化路径使用 `body`，详情请求提交普通内容后不再写回 `summary`。
2. 内容列表的 `onSelect` 由页面层包装：先调用 `details.setDetailTab('body')`，再调用现有 `openDetail(eventId)`。因此重复选择相同 id 也能同步重置，而列表选择权仍归 `useIngestEvents`。

不使用 React `key` 强制重挂 `ContentDetailPanel`，避免丢失视频元素、详情滚动位置和正在进行的子操作状态。

## 布局约束

在嵌入内容采集工作区中，详情 reader 使用比通用电影级样式更明确的作用域选择器，并固定：

- `width: 100%`；
- `min-width: 0`；
- 不改变现有 `position: relative`、高度、overflow 和动画禁用规则。

详情 tab 网格继续使用 `repeat(4, minmax(0, 1fr))`。每个 `.ingest-tab-trigger` 增加 `min-width: 0`，保证按钮内的单行标签不会把网格列撑大。现有省略号、移动端标签和响应式规则保持不变。

## 错误与竞态

- 详情请求失败：tab 仍为 `body`，显示现有错误状态。
- 快速 A-B-A 切换：现有 request sequence 继续阻止旧响应提交；每次点击只同步更新 tab，不改变请求所有权。
- 重复点击当前内容：只重置 tab，不创建重复请求。
- 摘要生成完成：只更新详情数据，不抢走用户当前 tab。
- 内容被删除或分类切换导致选择清空：沿用现有选择与空态逻辑。

## 测试

实施采用测试先行：

1. 在详情组合测试中先锁定 `detailTab` 初始值为 `body`，并证明 `loadDetail` 不再将普通内容切到 `summary`。
2. 锁定页面选择包装器的顺序：每次列表选择先调用 `setDetailTab('body')`，再调用 `openDetail(eventId)`，覆盖相同 id 的重复选择语义。
3. 在壳层 CSS 合同测试中锁定嵌入 reader 的 `width: 100%`、`min-width: 0`，以及 tab trigger 的 `min-width: 0`。
4. 运行前端电影级场景测试、类型检查和生产构建。
5. 在真实生产页面相同窗口状态下验证：首次加载、切到 AI 总结后重复点击当前内容、切换分类后自动选择三条路径均回到“转写原文”。
6. 对每个状态读取 pane、reader、tab grid 和四个按钮的几何；reader 与 grid 宽度不得因 active tab 改变，四列宽度应一致且不越界。

## 验收标准

- 打开内容采集页并自动选中内容后，“转写原文”处于 active 状态。
- 从任意其他 tab 重复点击当前内容，立即回到“转写原文”。
- 切换到另一条内容时，加载阶段和完成阶段均保持“转写原文”。
- 右侧 pane、reader 和 tab grid 的宽度不随当前 tab 内容变化。
- 四个 tab 均匀占满详情栏，无挤压、溢出、重叠或异常截断。
- 视频播放、详情滚动、转写工作台、摘要生成及其他详情操作保持可用。
